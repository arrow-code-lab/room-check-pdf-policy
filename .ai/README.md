# .ai/ — 計画資産の置き場所

このフォルダは `agent-kit-v2` の**出力先**です。エージェント（`_plan` / `_impl` / `_review` 等）が生成する計画資産を、**チームで共有できる形で git 追跡**します。

`.claude/` の外にあるのは、導入先プロジェクトの `.gitignore` / `.claude/.gitignore` を書き換えずに追跡境界を表現するためです（`.claude/` を丸ごと ignore しているプロジェクトでもそのまま効きます）。

## 構造

```
.ai/
├── .gitignore                     ← 追跡。何も除外しない（理由はファイル内のコメント参照）
├── .gitattributes                 ← 追跡。* text=auto eol=lf（このフォルダ内スコープ）
├── README.md                      ← このファイル
├── work/{Issue番号}/              ← 追跡。plan.md / task_1..k.md / handoff.md
├── specs/                         ← 追跡。spec-{yyyyMMdd-HHmmss}.md
│   ├── assets/{spec-id}/          ← 追跡。その spec の資料（モック・図・設計メモ）
│   └── rejected/{spec-id}.md      ← 追跡。棄却した案（spec ごとに 1 ファイル）
├── retro/{yyyy-MM}/issue-{n}.md   ← 追跡。完了時の振り返り
└── local/                         ← 非追跡ゾーン
    ├── .gitignore                 ← 追跡。`*` ＋ `!.gitignore` の 2 行だけ
    └── security/ loop/ tmp/ logs/ ← 実行時状態・ログ・一時物・未修正の脆弱性レポート
```

## 守るべきこと

### local/ は共有しない

`local/` 配下は**絶対に共有されません**。実行時状態・ログ・一時物・**未修正の脆弱性レポート**はここに置きます。

除外規則は `local/.gitignore` の 2 行**だけ**が持ちます。親（`.ai/.gitignore`）で `local/` を除外してはいけません。除外すると git がそのディレクトリへ降りず、`local/.gitignore` 自身を追跡できなくなり、**clone / worktree / 新メンバーの環境に除外規則が運ばれなくなります**（＝そこでは `local/` の中身が追跡対象になってしまう）。

`local/` へ書く主体は、書く前に `git check-ignore` で ignore 判定が真であることを実測し、偽なら**書かずに停止**します。

### 掃除は秘密を消さない

`/タスク完了整理` は完了した `work/{n}/` を削除しますが、**git 履歴と `refs/pull/{n}/head` は追記専用**です。一度コミットしたものは掃除しても消えません。

したがって掃除は「秘密を消す手段」ではありません。**最初から書かない**ことだけが有効な対策です。plan / task には次の 2 行が一律に適用されます。

1. spec 本文を**逐語転写しない**。パス参照＋節番号のみ（例: `根拠: .ai/specs/spec-20260806-1902.md §4-3`）。
2. 「現状コード抜粋」は**リポジトリに現存するコードの引用に限る**。攻撃手順・PoC・外部レポートからの引用は書かない。

例外は**自リポジトリのコードレビュー指摘**のみで、これは引き継ぎに不可欠なため `handoff.md §6` に逐語で書きます。セキュリティ監査・外部レポート由来の指摘は `local/` に置き、`§6` には参照 ID と深刻度のみを書きます。

### 1 Issue は 1 worktree

`handoff.md` は worktree 間で共有されません（worktree はそれぞれ独立した作業ツリーであり、Agent Kit Studio も共有の仕掛けを持ちません）。同一 Issue を 2 つの worktree に展開すると `handoff.md` が独立して分岐します。**1 Issue は 1 worktree で扱ってください。**

### 掃除の規約

`/タスク完了整理 {n}` を**最終レビュー承認後・マージ前**に実行します。

- `.ai/retro/{yyyy-MM}/issue-{n}.md` を生成する
- **同じコミットで** `work/{n}/` を `git rm` し、`fak-kind: done` の終端コミットを刻む
- `refs/wip/{n}/*`（退避 ref）を削除し、削除した ref 名を retro に列挙する
- **`specs/` は削除しない**
- ゲート: 最終レビュー承認済み ∧ retro 生成済みのときだけ削除する

## 引き継ぎの正本は git log

進捗・現在地・ビルド状態は**このフォルダのファイルには書きません**。コミットトレーラ（`fak-issue` / `fak-kind` / `fak-task` / `fak-step` / `fak-integration`）が正本です。`/引き継ぎ状況` が `git log` からその場で表示します。

**`git log`（トレーラ）が常に勝ちます。** `handoff.md` は git log に載せられない情報（環境前提・判断ログ・懸念・レビュー指摘・検証記録）の唯一の正本であり、競合する情報を書いてはいけません。

## 下流プロジェクトへの注意

- **conventional-commit 検査がある場合**、type に `wip` を許可リストへ追加してください（各ステップの WIP コミットが `wip(...)` を使います）。
- **CI がある場合**、Draft PR にも走らせてください。このフォルダの `handoff.md §7`（検証の実行記録）が唯一の回帰網になる構成では、検証が手動確認に依存します。
